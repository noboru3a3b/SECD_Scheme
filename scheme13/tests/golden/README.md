# ゴールデン出力について

11 件は **scheme12（`main` の `88db98b`）の出力そのもの**で、scheme13 は
バイト単位で一致しなければならない。これが「既存 `.scm` を無修正で動かす」の
唯一の判定基準（`dev_memo.md` §5.1）。

**`test-case6.scm` の 1 件だけは scheme13 の出力で採り直してある。**

残る4件（`lib13_test.scm` / `port_test.scm` / `exit_test.scm` /
`macro_print_test.scm`）は**既存資産ではなく scheme13 自身のテスト**で、
scheme12 には比べる相手が存在しない。こちらも scheme13 の出力をゴールデンに
してある。**`./scheme12_debug` を渡すとこの5件が落ちる。それは正常。**

| 種類 | 件数 | ゴールデンの出どころ |
| --- | --- | --- |
| 既存 `.scm` 資産 | 11 | scheme12（`88db98b`） |
| `test-case6.scm` | 1 | scheme13（理由は下記） |
| `lib13_test.scm`（R5RS の補い。8日目、13日目に多値と dynamic-wind を追加） | 1 | scheme13 |
| `port_test.scm`（ポート。10日目） | 1 | scheme13 |
| `exit_test.scm`（`exit`。15日目） | 1 | scheme13 |
| `macro_print_test.scm`（`macro-print`。17日目） | 1 | scheme13 |

`exit_test.scm` は**出力だけでなく終了コード（3）が本体**である。
`.scm` 1本では `exit` を一度しか呼べないので、終了コードの一覧
（引数なし / `#t` / `#f` / 整数 / `quit`）はゴールデンではなく
`run_golden.sh` の「終了コード」の節が式ごとに見ている（決定70）。

`macro_print_test.scm` の出力には**ソース位置（行・桁）が乗る**。
**このファイルの行を動かすとゴールデンがずれる**ので、足すときは末尾に足すこと。

## なぜこの 1 件だけ別扱いなのか

このファイルは**原典 `micro_Scheme8.lisp` のテストスイート**で、式とその期待値が
交互に並んでいる（`micro_scheme8_notes.md` §6.1）。原典の REPL は
`(test-start)` から `(test-end)` の間、式を1つ評価するごとに次の S 式を
期待値として読んで照合する。

scheme12 はこの機構を「`LDC #t` にする無視扱い」にしたため、裸の期待値 `A` を
評価しようとして必ず落ちていた。その時の出力が

    Fatal error: scheme12 VM error: unbound global: A

で、**処理系自身の名前とエラー文言**が中身だった。

- **5日目**: scheme13 のエラーはソース位置つきになる（`dev_memo.md` §4.2）ので、
  ここは必ず変わる。scheme13 の出力で採り直した。
- **6日目**: **テスト機構そのものを復活させた**（決定29）。いまは 145 項目が
  最後まで走り、`( total: 145  pass: 132  NG: 13 )` で終わる（exit=0）。

## 13 件の NG は「直すべきバグ」ではない

すべて scheme12 が原典から意図的に変えた点の帰結で、`dev_memo.md` §2 が
凍結仕様として認めているもの。内訳:

| 件数 | 内容 | 根拠 |
| --- | --- | --- |
| 10 | クロージャ・継続の表示。原典は `(CLOSURE <命令列> <環境>)`、scheme13 は `#<closure:(x)>` / `#<continuation>` | §2.1 |
| 2 | `(begin)` と `(if #f 10)` が `NIL`。原典は `:UNDEF` | §2.4 |
| 1 | `(test-start)` が `TRUE`。原典は CL の `T` | §2.1（真偽値は専用の型） |

**この 13 という数が動いたら、それは回帰。** ゴールデンが出力全体を
バイト単位で押さえているので、どの項目が変わったかまで差分に出る。

## 期待値の照合の仕方

期待値は Common Lisp のリーダを通った綴りなので**すべて大文字**
（`(quote a)` の期待値が `A`）。scheme13 のリーダは大小文字を保存するため、
値そのものの `equal?` では一致しない。転写の意図は「表示がこうなる」なので、
**write 表現を大小文字を無視して比べる**ことにした（`test_matches`）。
これで symbol / `TRUE` / `FALSE` / `NIL` が素直に通る。
