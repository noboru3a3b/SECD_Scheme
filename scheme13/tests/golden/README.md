# ゴールデン出力について

11 件は **scheme12（`main` の `88db98b`）の出力そのもの**で、scheme13 は
バイト単位で一致しなければならない。これが「既存 `.scm` を無修正で動かす」の
唯一の判定基準（`dev_memo.md` §5.1）。

**`test-case6.scm` の 1 件だけは scheme13 の出力で採り直してある**（5日目）。

理由: このファイルは裸の期待値 `A` を評価しようとして必ず失敗する（原典の
テスト機構が scheme12 で失われているため。`micro_scheme8_notes.md` §6.1）。
そのため出力が**処理系自身のエラー文言**になり、scheme12 のものは

    Fatal error: scheme12 VM error: unbound global: A

だった。処理系の名前が本文に入っている上、scheme13 は `dev_memo.md` §4.2 に
従ってエラーへソース位置を足すので、ここは必ず変わる。12 件のうち処理系由来の
エラー文字列を含むのはこの 1 件だけ（他の 11 件に出てくる "scheme12" は
`.scm` 側が `display` している文字列なので変わらない）。

判定基準は「exit=1 で、`A` が未定義である旨のエラー」。
関連する決定は `dev_memo.md` §5.1 と §6 の 3日目・決定16、5日目。
