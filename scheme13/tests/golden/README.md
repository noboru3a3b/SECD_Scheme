## `errors/` と `repl/` — 27日目に足した2つ

上の表のゴールデンは、どれも**正常に走りきるプログラムの出力**である。
27日目に、そこから外れる2つの筋道をゴールデンにした（決定135〜137）。
どちらも**標準出力・標準エラー・終了状態の3つを別々に**押さえる。

| ディレクトリ | 何を押さえるか | 入力 |
| --- | --- | --- |
| `errors/` | **エラーで止まるときの包み**。`Fatal error:` の見出し、`--load` に渡した実際のパス、行・桁、キャレット行、終了状態 1、stderr に出ること、**stderr へ書く前に stdout を流す**こと | `tests/errors/*.scm` |
| `repl/` | **人が REPL を触る筋道**。起動の挨拶、プロンプト、値が返ること、エラーで死なないこと、`(help)`、`Ctrl-D` で `Bye!`、`(exit 3)` の終了状態 | `tests/repl/*.in` |

**どちらも `.out`（標準出力）と `.err`（標準エラー）に分かれている。**
`errors/` は終了状態が必ず 1 なので `.exit` を置いていない（1 でなければ
その時点で不合格）。`repl/` は 0 と 3 の両方があるので `.exit` がある。

`errors/type_error.mix` だけが3つ目の形で、**両ストリームを同じ先へ混ぜた
とき**の出力である。`.out` と `.err` を別々に比べても**順序は現れない**ので、
「stderr へ書く前に stdout を流す」ことはこの1本だけが押さえている（決定137）。

理由と各ファイルの主張は `tests/errors/README.md` と
`tests/repl/README.md` にある。**`errors/` のゴールデンにはパスと行・桁が
乗る**ので、`.scm` の行を動かすとずれる。足すときは末尾に足すこと。

## なぜこの 1 件だけ別扱いなのか

このファイルは**原典 `micro_Scheme8.lisp` のテストスイート**で、式とその期待値が
交互に並んでいる（`micro_scheme8_notes.md` §6.1）。原典の REPL は
`(test-start)` から `(test-end)` の間、式を1つ評価するごとに次の S 式を
期待値として読んで照合する。

scheme12 はこの機構を「`LDC #t` にする無視扱い」にしたため、裸の期待値 `A` を
評価しようとして必ず落ちていた。その時の出力が

    Fatal error: scheme12 VM error: unbound global: A

で、**処理系自身の名前とエラー文言**が中身だった。

- **5日目**: scheme13 のエラーはソース位置つきになる（`dev_memo.md` §4.2）ので、
  ここは必ず変わる。scheme13 の出力で採り直した。
- **6日目**: **テスト機構そのものを復活させた**（決定29）。いまは 145 項目が
  最後まで走り、`( total: 145  pass: 132  NG: 13 )` で終わる（exit=0）。

## 13 件の NG は「直すべきバグ」ではない

すべて scheme12 が原典から意図的に変えた点の帰結で、`dev_memo.md` §2 が
凍結仕様として認めているもの。内訳:

| 件数 | 内容 | 根拠 |
| --- | --- | --- |
| 10 | クロージャ・継続の表示。原典は `(CLOSURE <命令列> <環境>)`、scheme13 は `#<closure:(x)>` / `#<continuation>` | §2.1 |
| 2 | `(begin)` と `(if #f 10)` が `NIL`。原典は `:UNDEF` | §2.4 |
| 1 | `(test-start)` が `TRUE`。原典は CL の `T` | §2.1（真偽値は専用の型） |

**この 13 という数が動いたら、それは回帰。** ゴールデンが出力全体を
バイト単位で押さえているので、どの項目が変わったかまで差分に出る。

## `debug_test.scm` — 命令セットの追随を機械に任せる（30日目）

§1.5 は `trace-on` / `trace-off` / `compile` / `disassemble` / `globals` /
`macros` / `help` を「この処理系の看板」とし、とくに**「逆アセンブル表示は、
命令セットを変えるたびに追随させること」**と定めている。30日目に測ったところ、
**7つのうち出力に後ろ盾があったのは `help` と `macro-print` の2つだけ**だった
（決定145）。`compile` / `disassemble` / `globals` / `macros` は `(help)` の
文面に名前が載っているだけで、`trace-on` に至っては `test_improvements.scm` が
**名前を含む文字列を印字していただけ**である。

`debug_test.scm` の第1節は、**21個の命令をすべて出す**ように式が選んである。
命令セットに手が入れば必ずどこかが動くので、**§1.5 の「追随させること」が
人の目から機械へ移る**。覆えているかはこう確かめる:

```sh
# ゴールデンに現れる命令
grep -oE '^\s*\[[0-9]+\] [A-Z-]+' scheme13/tests/golden/debug_test.scm.out \
  | awk '{print $2}' | sort -u > /tmp/covered.txt
# 実装が持つ命令
sed -n '/enum class Op/,/};/p' scheme13/scheme13.cpp | tr ',' '\n' \
  | grep -oE '\b[A-Z_]{2,}\b' | sed 's/ARGS_AP/ARGS-AP/' | sort -u > /tmp/allops.txt
comm -23 /tmp/allops.txt /tmp/covered.txt     # 空であること
```

**命令を足したらこれが空でなくなる。** そのときは `debug_test.scm` の第1節に、
その命令を出す式を足すこと。

**`globals` はここに入れない**（26日目の決定136）。大域名が増えるたびに動くので、
採り直しが「何かを壊した合図」にならない。実際に28・29日目で 243 → 275 と動いた。
**`macros` は入れてある** — 一覧が2件で、増えるのはマクロを足したときだけだから。

トレースは**意図して最小**にしてある。`(fact 3)` を実況させると608行になり、
ゴールデンとして「何が変わったか」が読めない。見たいのは「出ること・止まること・
5つの欄（PC / Instruction / Stack / Environment / Dump）が揃っていること」で、
それには `(+ 1 2)` の5命令で足りる（決定146）。

**足すときは第4節（トレース）の前に足すこと。** トレースは以降のすべての評価を
実況するので、後ろに置いたものは巻き込まれる。

## 期待値の照合の仕方

期待値は Common Lisp のリーダを通った綴りなので**すべて大文字**
（`(quote a)` の期待値が `A`）。scheme13 のリーダは大小文字を保存するため、
値そのものの `equal?` では一致しない。転写の意図は「表示がこうなる」なので、
**write 表現を大小文字を無視して比べる**ことにした（`test_matches`）。
これで symbol / `TRUE` / `FALSE` / `NIL` が素直に通る。
