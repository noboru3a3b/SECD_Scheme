# エラーで止まる .scm（27日目）

**ここにあるのは「エラーを出して止まること」自体が主張のファイルである。**
scheme13 に Scheme レベルの例外捕捉は無い（`dev_memo.md` §1.4-3）ので、
エラーを踏んだ時点で処理系ごと止まる。したがって1ファイルにつき1つの
エラーしか見られず、普通のゴールデン（`tests/golden/*.out`）には書けない。

`run_golden.sh` の「エラーの包み」の節がこれを走らせ、**標準出力・標準エラー・
終了状態の3つを別々に**ゴールデンと突き合わせる。

## なぜ selftest_errors() だけでは足りないのか

`--selftest` の `selftest_errors()` が見ているのは **`e.what()`、つまり本文だけ**
である（`eval_error_body()`）。`selftest_positions()` は `format_error()` の
キャレット行まで見るが、**リーダのエラーだけ**で、しかも架空のファイル名
（`t.scm`）を使う。つまり27日目まで、以下は**どのテストも見ていなかった**:

| 見ていなかったもの | どのファイルが押さえるか |
| --- | --- |
| `Fatal error: ` の見出し | 全部 |
| `--load` に渡した**実際のパス**が出ること | 全部 |
| **実行時**エラーのキャレット行（selftest はリーダのぶんだけ） | `type_error` ほか |
| **終了状態が 1** であること | 全部 |
| エラーが **stderr** に出て stdout には出ないこと | 全部 |
| **stderr へ書く前に stdout を流す**こと | `type_error` の `.mix`（下記） |
| 読み取りエラーだと**1行も実行されない**こと | `reader_error`（stdout が空） |

## 各ファイルが押さえているもの

| ファイル | 主張 |
| --- | --- |
| `type_error.scm` | 型エラーの包み一式。**エラーより前の出力は残り、後ろは実行されない** |
| `unbound.scm` | 未定義の大域。`note:` の行がつく（§4.2） |
| `reader_error.scm` | 読み取りエラー。**先に全部読むので、1行も実行されない**（stdout が空） |
| `arity.scm` | 引数の数。**呼ばれた側の名前**を出す（§4.2） |
| `div_zero.scm` | `(/ 1 0)` はエラー（凍結仕様 §2.3）。26日目に後ろ盾ゼロと測れた行 |
| `macro_position.scm` | マクロが生んだ式のエラーが**利用者の書いた行**を指す（決定52・53） |
| `user_error.scm` | Scheme の `error` 手続き |

## `.mix` — 2つのストリームを混ぜたときの順序

**`.out` と `.err` を別々に比べても、両者の順序は現れない。** 別ファイルなら、
どちらが先に書かれても中身は同じだからである。ところが `main` が
stderr へ書く前に `std::fflush(stdout)` していないと、**両方を同じ先へ
リダイレクトしたとき**に「エラーより前の出力」がエラーの**後ろ**へ回る
（stdout はファイル向けだと全バッファリングになり、流れるのが `exit` のときになる）。

27日目に、足したテスト自体を変異法で確かめて見つかった穴である（決定137）。
`type_error.scm` にだけ `.mix`（`> file 2>&1` で採った出力）を置き、
`run_golden.sh` が `.mix` のあるファイルだけこれを見る。
**順序を主張しているのはこの1本だけ**なので、他へ増やす必要はない。

**ゴールデンにはファイルのパスと行・桁が乗る。** 行を動かすとずれるので、
足すときは末尾に足すこと（`macro_print_test.scm` と同じ約束）。
